# FlowTrack Order Workflow - Full Updated Release - 2026-08-21

This package is the corrected Order workflow implementation based on the supplied interactive prototype and backend workflow specification.

Key points:

- Original general Workflow Setup remains available.
- Dedicated Order Workflow Setup remains separate and is Order-only.
- Create Order reads the dedicated Order Workflow Setup and requires a valid published workflow with configured stage task packs/items.
- Creating an Order generates the configured Order stages/tasks and activates the first applicable task.
- Active legacy Orders are normalized/rebound to the dedicated Order workflow so obsolete workflow phases do not continue to render in Order Details.
- Order Details renders stage names, colors and task rows dynamically from the configured Order workflow while keeping the prototype-aligned visual structure.
- Task action buttons are generated by backend descriptors rather than hard-coded Blade-only behavior.
- Workflow action handling includes PO intake, artwork review/revision/client decision/sample path, production/QC issue handling, shipment, billing and payment entry points.
- Task automation uses a stable hidden automation_key, so display-name changes do not remove backend behavior.
- Required task documents are enforced through backend task/document rules.
- Sequencing and stage progression remain backend-controlled.
- Task/workflow data is eager-loaded to avoid introducing N+1 queries in Order Details.

## Required local update commands

```bash
mkdir -p storage/framework/views storage/framework/sessions storage/framework/cache/data bootstrap/cache
php artisan migrate
php artisan optimize:clear
```

If active legacy Orders still need a one-time normalization after deployment, run:

```bash
php artisan flowtrack:sync-order-workflow
```

Then save the dedicated Order Workflow Setup once.
