# Remote Area Master Data — 2026-09-03

## Scope

The existing **Remote Areas** Master Data editor now supports the structure used by the UPS Remote Area / Extended Area spreadsheet without adding a database table. The new values are stored in `master_records.metadata`, preserving the existing `master_records` architecture and existing records.

Each Remote Area Surcharge record can store:

- Carrier (`metadata.carrier`, default `UPS`)
- Country (`metadata.country`)
- IATA / country code (`metadata.iata_code`)
- Postal Code From (`metadata.postal_code_from`)
- Postal Code To (`metadata.postal_code_to`)
- City (`metadata.city`)
- Origin Surcharge classification (`metadata.origin_surcharge`)
- Destination Surcharge classification (`metadata.destination_surcharge`)
- Optional existing FlowTrack Extra Charge (`metadata.extra_charge`)
- Notes/description, status and sort order using existing Master Data fields

`master_records.name` remains an internal display label generated by the editor from Country + Postal Range / City.

## Backwards compatibility and Order matching

Existing records that contain `metadata.postal_code` continue to display and participate in exact postal-code matching. New UPS-style rules do **not** need to duplicate that legacy key; `remoteAreaForPostalCode()` now reads `postal_code_from` / `postal_code_to` directly.

Order matching supports:

- exact legacy `metadata.postal_code` values;
- exact UPS-style rows where Postal Code From = Postal Code To;
- numeric equal-width ranges, including the From and To boundaries; and
- same-shape alphanumeric ranges such as `AB100`–`AB199` and `SW1A1AA`–`SW1A1AZ`.

Matching is case-insensitive and ignores whitespace. Exact rows take precedence over broader range rows. The Order detail flag, invoice preview, workflow invoice payload and server-side invoice surcharge all use the same matcher and the actual Order shipping postal code for display. City-only rows are stored but are not matched from a postal code alone.

## Validation

- Carrier, Country and two-letter IATA code are required in the UI.
- A rule requires either Postal Code From or City.
- Postal Code To defaults to Postal Code From when omitted.
- Same-shape numeric or alphanumeric ranges reject `To < From`.
- Origin and Destination surcharge values are restricted to the classifications present in the supplied UPS workbook.
- Duplicate rules are detected by Carrier + Country + IATA + Postal Range + City rather than globally by postal code.
- Extra Charge remains optional and is validated as a non-negative amount up to `999999.99`.

## UI

The Add/Edit form now shows Carrier, Country, IATA code, City, Postal Code From/To, Origin Surcharge, Destination Surcharge, optional Extra Charge, Status, Sort Order and Notes.

The list table now shows Code, Carrier, Country/IATA, Postal Range or City, Origin Surcharge, Destination Surcharge, Extra Charge, Status and Actions. Search includes the new UPS fields.
